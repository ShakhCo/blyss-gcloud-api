## Directory Purposes

**src/**
- Purpose: All application source code
- Contains: Routes, middleware, schemas, utilities, config, database
- Key files: `server.js` (entry point), `routes/index.js` (router aggregation)

**src/routes/**
- Purpose: HTTP request handlers organized by feature domain
- Contains: 17 route modules mapping to URL paths
- Key files:
  - `index.js`: Aggregates all route modules and applies middleware

**src/middleware/**
- Purpose: Cross-cutting concerns (authentication, validation, security)
- Contains: 3 middleware modules
- Mounted in `src/routes/index.js` before route handlers

**src/schemas/**
- Purpose: Input validation rules for all endpoints
- Contains: 14 schema files using Zod library
- Pattern: One file per domain (auth, booking, business, etc.)

**src/utils/**
- Purpose: Reusable business logic and integrations
- Contains: 11 utility modules
- Imported by: Routes, middleware, other utilities

**src/config/**
- Purpose: Non-code configuration
- Contains: File upload middleware setup
- Imported by: Routes that handle multipart/form-data

**src/db/**
- Purpose: Database connection and initialization
- Contains: Firestore instance
- Imported by: All routes and middleware

**docs/**
- Purpose: Manual API documentation
- Contains: API_DOCS.md, AUTH_API_DOCUMENTATION.md, etc.

**firebase.json**
- Purpose: Firebase project and Cloud Functions deployment config
- Location: Project root

**firestore.indexes.json**
- Purpose: Composite index definitions for Firestore queries
- Contains: Indexes for common query patterns (bookings by date, businesses by location, etc.)

**.planning/codebase/**
- Purpose: Codebase analysis documents (generated by GSD)
- Generated: ARCHITECTURE.md, STRUCTURE.md, CONVENTIONS.md, TESTING.md, CONCERNS.md

## Key File Locations

**Entry Points:**

- `src/server.js`: HTTP server startup and middleware setup
  - Loads dotenv, initializes Express, applies helmet + CORS
  - Mounts all route handlers from `src/routes/index.js`
  - Starts listening on PORT (default 3000)

- `src/routes/index.js`: Router aggregation
  - Imports all 17 route modules
  - Applies `verifySignature` middleware to protected routes
  - Mounts routes at base paths (/auth, /bookings, /telegram, etc.)

**Configuration:**

- `package.json`: Node.js dependencies (Express, Firestore, Zod, OpenAI, etc.)
- `firebase.json`: Firebase CLI config
- `.firebaserc`: Firebase project ID
- `firestore.rules`: Firestore security rules (if used)
- `.env`: Environment variables (OPENAI_API_KEY, ESKIZ_TOKEN, TELEGRAM_BOT_TOKEN, JWT_SECRET, API_SECRET, etc.)

**Core Logic:**

- `src/middleware/authenticate.js`: JWT verification, user data enrichment
- `src/middleware/telegramAuth.js`: Telegram Mini App validation, dual-token fallback
- `src/schemas/auth.js`: Login/register/OTP validation
- `src/utils/jwt.js`: Token generation/verification
- `src/utils/bookingLimits.js`: User booking limit checks
- `src/routes/bookings.js`: Booking CRUD, availability calculation

**Testing:**

- `src/server.test.js`: Basic integration test
- No other test files present (minimal test coverage)

## Naming Conventions

**Files:**

- Routes: `lowercase.js` (e.g., `bookings.js`, `businesses.js`)
- Schemas: `lowercase.js` in `schemas/` (e.g., `booking.js`, `business.js`)
- Utilities: `lowercase.js` in `utils/` (e.g., `jwt.js`, `eskiz.js`)
- Middleware: `descriptive-lowercase.js` (e.g., `authenticate.js`, `telegramAuth.js`)
- Config: `descriptive-lowercase.js` (e.g., `multer.js`)

**Directories:**

- Plural for collections: `routes/`, `schemas/`, `middleware/`, `utils/`, `config/`
- Singular for single modules: `db/` (database), `src/` (source)

**Variables and Functions:**

- camelCase for functions: `generateTokenPair()`, `sendOtpSms()`, `uploadFile()`
- camelCase for variables: `accessToken`, `userId`, `businessId`
- SCREAMING_SNAKE_CASE for constants: `API_SECRET`, `JWT_SECRET`, `MAX_TIMESTAMP_DIFF`
- PascalCase for schema enums: `bookingStatusEnum` (Zod enum)

**Firestore Collections:**

- lowercase: `users`, `businesses`, `bookings`, `otps`, `telegram_otps`
- Nested: `businesses/{id}/services`, `businesses/{id}/employees`, `businesses/{id}/customer_conversations`

**API Response Fields:**

- snake_case in JSON: `customer_id`, `booking_date`, `start_time`, `duration_minutes`, `user_type`
- Special: `error_code` (standardized error identifier)

## Where to Add New Code

**New Feature:**

1. **Create schema** in `src/schemas/[feature].js` if new input types needed
2. **Create route module** in `src/routes/[feature].js`
3. **Mount route** in `src/routes/index.js` with appropriate middleware:
   ```javascript
   router.use('/feature', verifySignature, featureRouter);  // Protected route
   // or
   router.use('/feature', featureRouter);  // Public route (handles auth internally)
   ```
4. **Add tests** in `src/[feature].test.js` (co-located with source)

**New Component/Module:**

1. If business logic: Create in `src/utils/[module].js`
2. If middleware: Create in `src/middleware/[module].js` and apply in `src/routes/index.js`
3. If database access: Use `import { db } from '../db/db.js'` to access Firestore
4. If external service: Create wrapper in `src/utils/[service].js`

**Utilities:**

- Shared helpers in `src/utils/[name].js`
- Example: Token generation → `src/utils/jwt.js`, SMS sending → `src/utils/eskiz.js`
- Imported by routes and other utilities

**Schemas:**

- One file per domain: `src/schemas/[domain].js`
- Group related schemas in same file (e.g., create, update, query schemas)
- Pattern:
  ```javascript
  export const createXSchema = z.object({ ... });
  export const updateXSchema = z.object({ ... });
  export const queryXSchema = z.object({ ... });
  ```

**Routes:**

- Mount in `src/routes/index.js` before `default export`
- Apply middleware inline:
  ```javascript
  router.post('/path', verifySignature, validate(schema), authenticate, (req, res) => { ... });
  ```
- Access `req.validated` after validate middleware, `req.user` after authenticate
